# Giải đấu (Tournament mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thêm trang `/giai` cho phép BTC tổ chức giải cầu lông phong trào nhiều nội dung (đăng ký qua link → bốc thăm → điều phối sân → nhập tỉ số → bảng xếp hạng/nhánh), chạy hoàn toàn ở máy local cho tới khi chủ sân duyệt.

**Architecture:** Logic giải là các hàm thuần trong `lib/tournament/` (có test `node --test`). Dữ liệu ở các collection PocketBase mới (không đụng `rooms`/`players`), quyền kiểm tra bằng rule + `pb_hooks/tournament.pb.js`. Giao diện là route tĩnh `app/giai/` dùng lại `lib/pb.ts`, `lib/alerts.ts`, `app/QrCode.tsx`, `app/QrScanner.tsx`.

**Tech Stack:** Next.js 16.3.6 (`output: 'export'`), React 19, Tailwind v4, PocketBase v0.40.5 (JS SDK `pocketbase` ^0.28), Node 24 (`--experimental-strip-types`).

**Spec:** `docs/superpowers/specs/2026-10-29-giai-dau-design.md` — đọc trước khi làm bất kỳ task nào.

## Global Constraints

- Làm trên nhánh `giai-dau`. **Không push, không deploy lên VPS** cho tới khi chủ sân duyệt bản chạy local (yêu cầu của chủ sân). Commit local thì được.
- Mọi test/chạy thử dùng **PocketBase local** (`http://127.0.0.1:8090`), không gọi server thật `146-235-22-130.sslip.io`.
- Không sửa schema/rule của collection `rooms`, `players`, `users` (chỉ đọc `users.is_host`). Quan hệ tới `users` không `cascadeDelete`.
- `app/page.tsx` chỉ được sửa ở 2 chỗ: nút lối vào "Giải đấu" ở launcher/role_select và nhận dạng link `/giai?code=` trong `handleScanResult`.
- Trước khi viết code Next, đọc `node_modules/next/dist/docs/01-app/01-getting-started/03-layouts-and-pages.md` và `.../02-guides/building.md` (static export, `useSearchParams` cần `<Suspense>`).
- Giao diện tiếng Việt (có bản EN tối thiểu cho nhãn chính), phong cách neo-brutalist như app hiện tại (viền đen 3px, bóng `shadow-[4px_4px_0_0_#000]`, vàng `#facc15`/`#fcd34d`).
- Luật điểm, xếp hạng, nhánh: đúng các giá trị ở spec §6.1 (cap mặc định 21→30, 15→21, khác→points+9; BWF 16.2; bán kết A1–B2/B1–A2; tứ kết A1–B2, C1–D2, B1–A2, D1–C2; đồng hạng ba).
- Mỗi nội dung 4–12 đôi; chỉ 2 hoặc 4 bảng; `advance` 1 hoặc 2.
- `rest_minutes` mặc định 10; mỗi người gắn tối đa 3 tài khoản; `btc_code` ~8 ký tự bộ `ABCDEFGHJKMNPQRSTUVWXYZ23456789`.

### Task 2: Xếp hạng BWF 16.2 (`standings.ts`)

**Files:** Create `lib/tournament/standings.ts` (+`.test.ts`); thêm kiểu vào `types.ts`

**Interfaces:**
- Consumes: `matchResult`, `ScoringRule` (Task 1).
- Produces:
  - `type ResultInput = { a: string; b: string; scores: GameScore[]; winner: 'a'|'b'; walkover?: boolean }`
  - `type StandingRow = { entry: string; played: number; won: number; lost: number; gameDiff: number; pointDiff: number; rank: number; byLot: boolean }`
  - `computeStandings(entries: string[], results: ResultInput[], rule: ScoringRule, opts: { walkoverMode: 'walkover' | 'bwf'; withdrawn: string[]; rng: () => number }): StandingRow[]` (đã sắp theo rank)

- [ ] **Step 1: Test:**
  - Không hòa: thứ tự theo số trận thắng.
  - Hai đôi bằng số thắng → đôi thắng đối đầu xếp trên (dù hiệu số set kém hơn).
  - Ba đôi A,B,C cùng 2 thắng (bảng 4: A>B, B>C, C>A, mỗi đôi thắng D) với hiệu số set khác nhau → xếp theo hiệu số set **toàn bảng**.
  - Ba đôi bằng hiệu số set, hiệu số điểm A > B = C → A nhất, rồi B/C xét đối đầu.
  - Ba đôi bằng hết → `byLot: true`, thứ tự theo `rng` cố định (rng trả `[0.9, 0.1, 0.5]` → thứ tự xác định trong test).
  - Walkover: trận walkover tính 2–0 set (games 3) / 1–0 (games 1), mỗi set `points`–0.
  - `walkoverMode: 'bwf'` + `withdrawn: ['D']` → mọi trận của D bị loại khỏi bảng, D không có trong kết quả.
- [ ] **Step 2:** `npm test` → FAIL.
- [ ] **Step 3:** Cài đặt đệ quy: nhóm theo số thắng; nhóm 2 → đối đầu; nhóm ≥3 → hiệu số set (toàn bảng) → tách nhóm con, nhóm con 2 → đối đầu, ≥3 → hiệu số điểm → tương tự → bốc thăm.
